# AtomWeft 源码与许可证审查

审查日期：2026-10-04。发布维护者：KHZ-beep。范围：以 0.3.2 开发目录为基础整理的首次公开源码快照。

## 结论

在本次检查范围内，未发现需要把项目应用代码改用第三方许可证的直接代码复制证据。应用代码按维护者选择使用 MIT；第三方组件继续使用原有许可证。此结论是有限工程审查，不是完整代码查重、权利归属鉴定或无侵权保证。

## 本次检查

- 阅读结构解析、CIF 配位识别、SVG 场景、景深、编辑与项目导入、DrawingML/COM 导出、本地 HTTP 服务、加载项和安装脚本的主要实现。
- 检查声明及本机依赖包的许可证，保留 Gemmi、RDKit、Python、NumPy、Pillow 和 pywin32 相关文本；不将这些组件重新标注为 MIT。
- 检查本地服务的 loopback 绑定、Host/Origin 校验、随机会话令牌、文件大小及图形数量约束、标签转义和固定静态资源路由。
- 检查安装器解压路径约束、清单哈希验证、用户级注册、旧身份迁移及文稿保护逻辑。
- 使用发布文件白名单排除依赖二进制、开发日志、注册表备份、本机路径配置、个人项目、原始参考图片和临时界面截图。
- 对拟提交文件扫描已知开发机标识、用户路径、常见访问令牌和私钥标记；只报告命中位置，不输出凭据内容。
- 对少量独特注释进行公开网页精确短语检索，未找到可确认的同段源码来源；该抽样不能替代全量相似性分析，搜索引擎也不覆盖全部公开及私有代码。

## 修正与发布整理

| 项目 | 发现 | 处理 |
|---|---|---|
| 密集结构的连接推断 | 生成全部连接后才检查上限，可能过量分配内存 | 在 `infer_bonds` 中准备超过 16000 个连接时立即拒绝，并加入 260 原子的密集输入回归测试 |
| 应用许可证 | 开发目录没有确定的项目 LICENSE | 按维护者选择添加完整 MIT 许可、KHZ-beep 署名及 SPDX 文件头 |
| 第三方范围 | 根目录缺少清晰的第三方入口 | 添加 THIRD_PARTY_NOTICES.md、保留上游许可文本，并说明二进制分发仍须携带完整组件许可 |
| 安装包构建 | 原白名单不包含项目自身的版权文件 | 后续构建在安装包根目录与 app 目录中均包含 LICENSE、COPYRIGHT.md |
| 测试顺序 | 部分测试依赖先生成的场景文件，直接全量发现测试会失败 | 增加 `tests/run_all.py`，先创建 build 目录，再依次生成夹具和运行测试 |
| 隐私与提交身份 | 开发目录含本机运行数据 | 独立整理源码，使用 GitHub noreply 邮箱提交，不上传本机用户名、个人邮箱或工作路径 |

## 验证

发布目录执行 `python tests/run_all.py`：16 项 Python 测试、17 项 JavaScript 测试通过。包括格式解析、周期配位、编辑与撤销、原生图形输出、小球/键组合、景深连续性及输入拒绝。测试使用已安装的依赖包，未宣称在一台全新电脑完成依赖安装。

本次未重新安装插件或重新验收所有 Office 版本。既有 0.3.2 安装器未随本次源码提交上传；修正后的新二进制仍需重新构建、分配新版本并实机验收。

- 开发使用 AI 辅助。没有可供回溯的原始 Git 历史；首次提交如实记录本次快照，不补造历史或作者证据。
- 通用的球棍表示、旋转、凸包和明暗计算不能单独证明具体代码被复制；也不能据此保证具体实现不涉及他人权利。
- 未完成全球源码相似性检索、专利分析、商标核准、完整依赖漏洞扫描或所有传递依赖的逐文件法律审查。

- 测试 CIF 是简化构造模型，不含第三方数据库导出的实验记录。实际导入文件的许可由提供者确认。
- 项目 MIT 许可不改变 Gemmi 的 MPL 义务。新应用文件调用其 API，第三方源码与权利仍按第三方许可保留。
